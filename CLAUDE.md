## Что делаем (2026-10-05: вместо бота — веб-приложение для iPhone)

Владелец выбрал веб-приложение вместо Telegram-бота: сайт, который на iPhone добавляется на экран
«Домой» (Safari → Поделиться → На экран «Домой») и открывается на весь экран как приложение.
Размещение — GitHub Pages на аккаунте владельца (Haniken88), адрес вида haniken88.github.io/<репо>. Отдельный репозиторий — магазин (game-store) не трогать.
Код в публичном репозитории — владельцу сказано, секретов там нет.

Экран:
1. Овальный стол с местами (2–10): касание места — убрать выбывшего / вернуть; баттон
   перетаскивается пальцем; твоё место отмечаешь касанием. Позиция считается сама.
2. Свои 2 карты — сетка «номинал × масть», одно касание на карту, без набора текста.
3. Префлоп: совет пас / колл / рейз (и размер); ввод: был ли рейз, сколько, банк.
4. Флоп / тёрн / ривер: комбинация, дро, шанс выиграть в %, совет чек / ставка (размер) /
   колл / пас + одна строка «почему». На каждой улице — ставки соперников и банк.

## Важно (уже объяснено владельцу, не повторять каждый раз)

В казино/клубах и на турнирах телефон и подсказки во время раздачи запрещены (за это штраф
или дисквалификация); в онлайн-румах на деньги — бан и конфискация. Бот задуман для тренировки
и разбора раздач после игры. Владелец это услышал — больше не читать нотаций.
Уровень советов — крепкая база (диапазоны + шансы против цены колла), не солвер профи;
так и говорить, не обещать «выигрышную систему».

## Решения (принято, не переспрашивать владельца)

- Обычные HTML + CSS + JavaScript (модули ES), без React и без сборки. Работает офлайн
  (service worker + manifest), сервер не нужен — всё считается в телефоне.
- Оценка руки — свой код без сторонних библиотек. Шанс выиграть — Монте-Карло против N
  соперников, ответ за ~1 секунду на iPhone.
- Префлоп — таблицы стартовых рук по позициям, отдельно «никто не повышал» / «был рейз».
- Постфлоп — шанс выиграть против цены колла (pot odds), размеры ставок в долях банка.
- Тесты с первого дня: `node --test` (встроен в Node, зависимостей нет) — комбинации,
  сравнение рук, шансы (AA против KK префлоп ≈ 82 %).
- Дизайн выбран 2026-10-05: «Клубное сукно» (mockups/b-felt.html): тёмно-зелёный фон, стол с
  деревянным бортом и сукном, карты цвета слоновой кости, золото; шрифты Prata (цифры/заголовки) и
  Manrope (текст). Совет — светлая карточка внизу. Скриншоты макетов: `node mockups/shot.mjs b-felt`
  (нужен `python3 -m http.server 8091` из корня проекта).
- Стол как в казино: вытянутый, 9 мест, ДИЛЕР посередине верхней длинной стороны, место 1 справа
  от дилера, по часовой до 9 слева; 2–3 и 7–8 на закруглениях, 4–5–6 напротив дилера. Места
  подписаны номерами, под номером позиция (считается сама). Касание места — пусто/занято;
  кнопка D перетаскивается.
- Деплой: git push по SSH (ключ сервера уже есть в GitHub Haniken88); `gh` не установлен —
  репозиторий владелец создаёт сам на github.com (показать по шагам).

## Модель советов (переделана 2026-10-05 после жалоб владельца на «ложные проценты»)

- Против случайных рук расчёт сверен с калькуляторами (PokerStove/Equilab): `node scripts/compare-equity.mjs`.
- Соперники (src/ranges.js): поставивший — руки «по делу» плюс блефы; остальные — обычный префлоп-
  диапазон (НЕ «все попали в стол» — это давало QQ 1 %). «По делу» зависит от размера ставки: лучшие
  55 % / 40 % / 22 % его рук на этом столе (до полбанка / до банка / больше) + дро, если ставка ≤ банка.
  Доля блефа НЕ растёт со ставкой (владелец не согласен с теорией b/(1+2b), 2026-10-05): её выбирает
  владелец переключателем «Редко блефует 8 % / Обычно 20 % / Часто 35 %», при ставке > 1,5 банка ×0,75.
  Если решение меняется от типа соперника — совет говорит это («Но если он часто блефует — колл»).
- Повышаем, только если впереди против ставящего без блефов; колл — шанс против цены колла;
  на флопе дро без пары засчитывается на 87 % (дальше ещё ставки), кроме ва-банка.
  На ривере рейз — только если против рук «по делу» шанс ≥ 70 %.
- Префлоп-шанс — против тех, кто реально играет (одного/лимперов/повысившего), не против всего стола.
- Стек: до 15 ББ — «ва-банк или пас» (рейтинг один на один HAND_RANKS_HU, пары всегда в ва-банк до 10 ББ);
  ставка ≥ половины стека → ва-банк.
- Прогон 97 типичных раздач с ожидаемыми решениями: `node scripts/review.mjs` (входит в `npm test`),
  результат для владельца — docs/proverka-sovetov.md. Новая жалоба владельца → добавить раздачу сюда.
- Экран: банк вводится нажатием на «Банк» на столе (банк = деньги в центре, без ставки улицы),
  «Соперник поставил» — отдельно; строка «Блайнды · Твой стек» вверху; без зума от двойного касания.

- Глубина стека (2026-10-05, по книгам: ловля сета 15–20× цены колла в позиции, 25× без; SPR):
  префлоп — пары 22–JJ уравнивают рейз, если стек ≥ 18× (в позиции) / 25× (блайнды) цены колла;
  одномастные связки и тузы — в позиции или на ББ, рейз ≤ 4 ББ, стек ≥ 30× цены; ББ против мин-рейза
  защищает ~50 % рук; МБ доплачивает полблайнда в лимп-банке с ~55 % рук. После флопа: SPR < 3 со
  старшей парой+ — ва-банк; SPR > 6 одной парой не повышаем; дро при SPR ≥ 4 и ставке ≤ банка
  учитывает будущий выигрыш (неявные шансы). Стек соперника владелец вводить НЕ хочет — считаем по своему.

- 2026-10-05, чтобы ошибок было меньше: таблицы открытия — по опубликованным таблицам солвера (Preflop Wizard
  9-max/6-max, GTO Gecko), доли 9/12/14/16/21/28/45/40 % — в review.mjs есть граничные руки из этих таблиц.
  Защита ББ по цене: 50 % (≤2,5 ББ), 38 % (≤3,5), 28 % (≤4,5), 18 %. Против лимперов повышаем строже
  (лимпер = два игрока после тебя). «Спорно» (поле close): разница шанса и цены < 4 %, рука на границе таблицы.
- Кнопка «Не согласен» → «Отправить письмом себе» (mailto без адреса — адрес владельца в публичный код
  не вшивать) или «Скопировать». В тексте строка `#data {...}`. Владелец играет на телефоне, сидит за
